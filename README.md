## Features

| Feature | Description |
|---|---|
| **Phishing Detection** | Visual threat/clean status per email sourced from backend analysis |
| **VirusTotal Integration** | Donut chart showing clean vs. threat engine results with secure-rate percentage |
| **HaveIBeenPwned** | Breach count display for the sender's email domain |
| **AI Summarized Analysis** | OpenAI-powered natural-language summary of email threat indicators |
| **AI Mitigation Techniques** | Step-by-step recommended actions generated by OpenAI |
| **Email Selector** | Modal dialog to browse and switch between all forwarded emails |
| **Responsive Design** | Fully responsive grid layout (mobile → desktop) |
| **Account Management** | User profile header with logout functionality |
| **Animated UI Elements** | Conic-gradient spinning border on the email selector button |

## Getting Started

### Prerequisites

- **Node.js** ≥ 18.x
- **npm** ≥ 9.x (or **yarn** / **pnpm**)
- A running instance of the **SirenScan Backend** API

### Installation

```bash
git clone https://github.com/<your-org>/SirenScan-frontend.git
cd SirenScan-frontend
npm install
```

### Environment Variables

Create a `.env` file in the project root:

```env
VITE_API_BASE_URL=http://localhost:8080   # Backend API base URL
```

> Adjust the URL to match your backend deployment.

### Running in Development

```bash
npm run dev
```

The app will start at `http://localhost:5173` by default.

### Building for Production

```bash
npm run build
npm run preview   # preview the production build locally
```

Output is written to `dist/`.

## Architecture Overview

### Application Flow

```
┌──────────────┐     ┌──────────────┐     ┌──────────────────┐
│  User Login  │────▸│  Fetch Emails│────▸│    Dashboard     │
│  (OAuth/JWT) │     │  from API    │     │  (select email)  │
└──────────────┘     └──────────────┘     └──────┬───────────┘
                                                  │
                          ┌───────────────────────┼───────────────────────┐
                          │                       │                       │
                    ┌─────▼─────┐          ┌──────▼──────┐        ┌──────▼──────┐
                    │VirusTotal │          │HaveIBeen    │        │  OpenAI     │
                    │  Card     │          │Pwned Card   │        │  Cards (x2) │
                    └───────────┘          └─────────────┘        └─────────────┘
```

### Key Components

#### `Dashboard.tsx` *(Main View)*

The central component that renders the entire dashboard. It receives all data and callbacks via props.

| Prop | Type | Description |
|---|---|---|
| `UserProfile` | `UserProfile` | Authenticated user's profile information |
| `email` | `Email` | Currently selected email for detailed view |
| `emails` | `Email[]` | All forwarded emails |
| `onSelectEmail` | `(email: Email) => void` | Callback when user selects a different email |
| `onNavigateToVirusTotal` | `() => void` | Navigate to the VirusTotal detail page |
| `onNavigateToHaveIBeenPwned` | `() => void` | Navigate to the HIBP detail page |
| `onNavigateToOpenAI` | `() => void` | Navigate to the OpenAI analysis detail page |
| `onLogout` | `() => void` | Logout callback |
| `onOpenMobileMenu` | `() => void` | Open mobile sidebar/menu |

**Internal state:**

- `open` (`boolean`) — controls the email-selector `Dialog` visibility.

**Sections rendered:**

1. **Account Header** — user info & logout
2. **Email Selector Dialog** — modal list of all forwarded emails
3. **Metrics Grid** (3 columns on desktop):
   - Phishing Detection card
   - VirusTotal donut chart card
   - HaveIBeenPwned breach count card
4. **OpenAI Cards** (2 columns on desktop):
   - Summarized Analysis
   - Mitigation Techniques

#### `AccountHeader.tsx`

Top navigation bar displaying the user's email/avatar and providing logout + mobile menu actions.

#### `ui/dialog.tsx`

Radix-based shadcn/ui dialog primitives (`Dialog`, `DialogTrigger`, `DialogContent`, `DialogHeader`, `DialogTitle`).

### Data Model

#### `Email` (defined in `App.tsx`)

```typescript
interface Email {
  id: string;
  sender: string;
  subject: string;
  body: string;
  phishingDetected: boolean;
  virusTotalResults: {
    clean: number;
    threats: number;
  };
  breachCount: number;
  aiSummary: string;
  aiMitigation: string;
}
```

#### `UserProfile` (defined in `useUserEmail.ts`)

```typescript
interface UserProfile {
  email: string;
  name?: string;
  avatar?: string;
}
```

### Custom Hooks

| Hook | Purpose |
|---|---|
| `useUserEmail` | Fetches and exposes the authenticated user's profile (`UserProfile`) |

|---|---|

## API Integration

The frontend expects the backend to provide the following data per email:

| Endpoint (conceptual) | Data Returned |
|---|---|
| `GET /emails` | Array of `Email` objects with all analysis results pre-populated |
| `GET /user/profile` | `UserProfile` object |
| `POST /auth/logout` | Ends the user session |

> **Note:** Actual endpoint paths depend on your backend implementation. The frontend consumes data passed as props from the parent `App.tsx` component.
